Capabilities

不是网盘，而是可审计的汇交流水线

材料版本、作者确认、研究所审核、访问授权四条链路互相咬合，任何一步都可回溯、可验证、不可抵赖。

🧬

版本只增不改

材料版本、论文版本、审核记录与审计日志一旦写入即不可更新或删除；补充材料只能新增版本，历史结果始终可复现。

🔒

批次冻结快照

发起确认时冻结标题、作者、材料哈希与论文稿版本；后续修改论文不会影响已送审内容，杜绝“送审后换数据”。

✅

全员作者确认

支持 3 位内部作者 + 1 位外部作者逐一确认；撤回、异议均保留历史。全部确认后才能提交，异议即终止本轮。

🏛️

跨研究所隔离

研究所管理员只能受理、审核、审批本所论文；对照研究所账号用于验证越权拦截，权限校验同时落在过程与页面。

🔗

实验结果全链路追溯

结果 → 运行 → 代码/数据/配置/日志的具体版本。论文图 3 使用的数据版本、哈希与运行环境一目了然。

📥

受限数据受控共享

访问申请必须填写理由，管理员按“有效期 + 下载次数”批准；每次下载登记 IP 与时间，超次、过期、撤销都会拒绝。

-- 批次状态机：非法流转在任何入口都会被拒绝
CREATE OR REPLACE FUNCTION trg_batch_status_guard()
RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
  IF OLD.status IN ('DISPUTED','RETURNED',
                  'WITHDRAWN','ARCHIVED') THEN
    RAISE EXCEPTION '批次已结束，不得再改变状态';
  END IF;

  IF NOT (
       (OLD.status = 'DRAFT' AND
        NEW.status IN ('PENDING_AUTHORS','WITHDRAWN'))
    OR (OLD.status = 'UNDER_REVIEW' AND
        NEW.status IN ('ARCHIVED','RETURNED'))
       -- ... 其余合法路径
  ) THEN
    RAISE EXCEPTION '非法的批次状态流转';
  END IF;
  RETURN NEW;
END;
$$;

即使有人用 psql 直接 UPDATE，也必须通过同一套规则。

Access Control

六类身份，边界清晰

操作负责人作者维护所管理员使用者
创建批次✓—✓本所—
作者确认✓✓———
受理 / 审核———本所—
审批数据申请———本所—
下载受限材料✓✓✓本所需授权

为什么维护成员没有确认权？

维护成员（如协助整理材料的研究生）可以在授权范围内上传材料、登记实验，但不是论文署名作者， 因此不能代替作者确认“这批材料就是论文所用材料”。权限与责任分离，避免“代签”。

跨所隔离如何验证？

演示数据包含 INST-02 的对照论文与管理员账号。用 INST-02 管理员受理 INST-01 的批次会返回 FORBIDDEN，页面上也会提示“只有主管研究所管理员可以受理”。
